# Agent Note: 桌面端外部下载链接

Status: implemented

[English](2026-08-17-desktop-external-download-links.md) | 中文

## 问题

对话 Markdown 会把绝对报表 URL 正确渲染为带 `target="_blank"` 的链接，但 Electron 加固策略会拒绝所有新窗口请求，且没有把安全目标交给操作系统。因此，带签名的 Excel 导出链接看起来可交互，点击却会被静默丢弃。

渲染进程仍不得创建任意 Electron 窗口，也不得把 Harness 界面导航到不受信任的来源。报表 URL 还可能包含短期签名，其查询编码不能被安全地改写。

## 决策

桌面主窗口继续拒绝渲染进程创建的所有窗口。窗口打开处理器会先用纯函数 `allowedExternalHttpUrl` 校验目标，再返回 `deny`。用户明确点击的绝对 HTTP 或 HTTPS 目标会不经改写地交给 Electron `shell.openExternal`，由默认浏览器打开，同时 Harness 窗口保持原状。相对目标和其他所有协议仍会被拦截。

该处理器只安装到登录后的主窗口。登录和加载窗口继续使用 `hardenedWindow` 配置的无条件拒绝。如果操作系统拒绝打开已允许的目标，主进程会显示本地化错误对话框，不再留下另一次无反馈点击。

## 曾考虑的替代方案

**允许 Electron 创建子 `BrowserWindow`。** 被否决，因为这会把不受信任的对话链接变成应用自身拥有的浏览上下文，削弱现有弹窗隔离。

**把主 Harness 窗口导航到报表 URL。** 被否决，因为这会替换受管的本地应用，并丢失当前会话界面。

**在渲染进程内下载任意 URL。** 被否决，因为这会向渲染进程增加网络和文件系统能力，重复操作系统的下载路径，还需要更大的认证下载设计。

**打开前规范化 URL。** 被否决，因为规范化可能改变带签名的短期报表 URL 所使用的已编码查询字节。

## 后果

带签名的 HTTP(S) 报表链接现在会通过默认浏览器打开，并可完成正常下载流程。弹窗创建、相对导航，以及 `javascript:`、`data:`、`file:`、`mailto:` 目标仍保持不可用。

该行为由 URL 策略测试、桌面源码装配断言、TypeScript 编译和现有桌面测试集覆盖。本次修复不改变 Markdown 解析和普通浏览器组装。
