# Agent Note: GUI 与文档回归检查

Status: implemented

[English](2026-10-16-gui-documentation-checks.md) | 中文

## 问题

GUI 预期和生成文档可能与已发布组合漂移，而社区工作流仍然为绿。仅支持图片的附件提供方还会暴露零限额的禁用文档策略；拒绝该策略会使原本有效的图片会话无法读取历史。

## 决策

文档策略投影接受非负整数，包括基础服务的禁用零策略，同时拒绝负数、小数和非有限限额。此处只修改 wire 校验，不改变文档准入或提供方能力。投影回归保留真实的仅图片提供方，并校验其历史响应。

Win32 对话框的源码启动器通过 Node 模块解析器定位 ESM loader，使 Vitest 模块运行器仍可驱动真实子进程。GUI 测试查询夹具实际安装的语言，并对发布的社区品牌生成快照；不改变生产文案，也不跳过失败场景。

Community CI 执行 GUI 套件和文档检查。生成目录来自当前源码，公共 JSDoc 说明实际参数和结果，双语引用保持同步。上游工作流记录明确适用范围，不把已移除的工作流描述为本分支实际安装的 CI。

## 考虑过的替代方案

**跳过失败或放宽检查：**不采用，因为过期夹具与受支持策略被拒绝需要不同修复。既有断言和文档校验继续启用。

**给仅图片提供方配置正文档限额：**不采用，因为这会宣称不支持的容量，而不是表达既有禁用状态。

**恢复全部上游工作流：**不采用，因为外部模型密钥、分发任务和平台 Runner 属于独立运维决策，不是本地文档完整性的前提。

## 结果

社区校验任务耗时增加，并在合并前捕获 GUI/文档漂移。本机真实 worker 检查仍只覆盖当前平台；非 Windows 通过不代表 Windows 上的 Win32 对话框已验收。这些检查不触发生产部署。
